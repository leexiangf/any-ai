What is an Amp plugin

TypeScript or JavaScript modules Amp loads to extend the agent — with clear skill and mode boundaries.

You land here when search or a listing says “Amp plugin” and you need a precise definition before installing anything. An Amp plugin is code Amp executes in your environment. It is not a marketplace SKU by itself, and it is not the same thing as a skill file or a built-in agent mode — though a plugin can register skills or modes.

One-line definition A .ts / .js module (or directory with index.ts) that Amp loads and runs

Entry shape Amp documents: default-export a function that receives PluginAPI from @ampcode/plugin.

What plugins can do

Per Amp’s plugin docs, a plugin may:

  • Handle lifecycle events (amp.on(...)) such as tool calls and results
  • Register custom tools (amp.registerTool(...))
  • Call built-in, plugin, or MCP tools via context helpers
  • Bundle and register skills (amp.registerSkill(...))
  • Add command-palette commands (amp.registerCommand(...))
  • Show UI prompts and notifications
  • Use Amp AI helpers and thread labels

Concrete listings on this market (for example @amp/finder or @amp/oracle) are plugins you install with documented CLI or Share flows — see how to install.

Where plugins load from

  • Personal

    Managed in Personal Settings / personal plugin repository. Apply everywhere you use Amp.

  • Workspace

    Managed by workspace admins. Apply to everyone in that workspace.

  • Project

    Files or directories under .amp/plugins/ at the repo root.

  • System

    ~/.config/amp/plugins/ (or Windows %USERPROFILE%\.config\amp\plugins\; honor XDG_CONFIG_HOME).

Same name → precedence is project → system → personal → workspace. Inspect with amp plugins list.

Plugin vs skill vs mode

  • Plugin

    Executable module with a Plugin API entrypoint. Can register tools, commands, events, UI, and optionally skills or custom agent modes. Runs as code — trust matters.

  • Skill

    Instruction / resource package (typically a directory with SKILL.md). A plugin can bundle skills and must call registerSkill — Amp does not auto-scan a plugin’s skills/ folder. A skill-only Git repo is not automatically an Amp plugin; follow the listing’s install verb (some markets use different commands).

  • Mode

    An agent configuration surface (model, prompt, tool set). Amp ships built-in modes; some additional modes ship as installable plugins (for example classic mode packages via amp plugins add --auto-update @amp/…). Installing a mode plugin does not turn every tool plugin into a mode — look for it in the mode picker after plugins: reload.

Trust and this directory

Plugins run on your machine. This site is a community install index (Any AI / AI-AAII), not Amp’s official marketplace and not a security audit. Prefer reviewing source, then installing from a listing’s real command block.

Shortest path after you understand the term

  1. Browse listed plugins and open one you trust.
  2. Install with the listing’s block — usually amp plugins add or a Share import ( full install guide).
  3. Verify with reload and list.

Failure branches (concept mix-ups)

  • “I cloned a skill repo and Amp did nothing”

    Cloning is not registration. Use the install command on the listing, or place a real plugin entry under a load path Amp documents.

  • “I installed a tool plugin but it is not in the mode picker”

    Tools ≠ modes. Check the author docs for where the feature appears, then not showing.

  • “Personal plugin vanished in this repo”

    Project-scoped same-name plugin wins. List sources and resolve precedence.

Success criteria

  • You can define an Amp plugin in one sentence without calling it a skill.
  • You can name at least two load locations and the precedence order.
  • You know the next page is install or develop, not more vocabulary.
