How to reload and list plugins

One verify loop after install or edit — then deep-link to each command page.

Use this overview when you finished an install (or a local plugin change) and want a single checklist: refresh the Amp session, then prove what loaded. Detailed command pages stay thin on purpose — plugins: reload for refresh only, amp plugins list for inspection only.

When to open this Just ran amp plugins add / dropped a file / edited index.ts

Goal: confirm Amp actually loaded the new code before you debug UI emptiness.

Shortest success path

  1. Make sure the CLI works in your shell:
    Checkamp --version
  2. In Amp, open the command palette (Ctrl+O) and run plugins: reload. Full notes: plugins: reload.
  3. Optional in-product check: run plugins: list from the same palette.
  4. In the shell, audit what Amp registered:
    Shellamp plugins list
    Full notes: amp plugins list.
  5. Exercise the plugin feature the author documents (tool, command, or mode). If the name never appears in list, stop verifying and reinstall from how to install.

Division of labor

  • Reload

    Mutates the running session so new files and imports take effect. Does not print a full audit. Does not download updates.

  • List

    Read-only evidence: names, sources, registered tools/commands. Does not refresh stale sessions by itself.

  • This page

    Orders them into one post-install verify loop and links the specialized pages.

Failure branches

  • List empty after reload

    Install never landed or landed in another scope/project. Follow add failed or re-check --target workspace vs machine-wide add.

  • List OK, feature missing

    Surface / precedence / limits — not showing.

  • Old behavior after edit

    You edited a non-winning copy. Use list to find the path Amp loaded, edit that path, reload again, or restart Amp once.

  • CLI missing entirely

    amp: command not found — fix PATH before trusting any list output.

Success criteria

  • Reload completed in the Amp session you use.
  • amp plugins list shows the expected plugin and source.
  • The documented tool, command, or mode is usable afterward.
