How to update Amp plugins

Refresh imports and CLI installs without confusing update with reload or blind overwrite.

Open this when a plugin already works and you need a newer upstream revision — not when tools are simply stale in the current session. Session refresh is plugins: reload. This page covers amp plugins update, Share-import refresh, and where --auto-update applies.

Update-related commands amp plugins update <name> amp plugins import … amp plugins add --auto-update @amp/<name>

Amp also documents asking in-thread whether imported personal/workspace plugins are out of date. Review diffs before you push hosted plugin repositories.

Shortest success path

  1. Identify how the plugin was installed: CLI add, Share import into personal/workspace repos, or a local directory drop. List first:
    Inspectamp plugins list
  2. For managed imports / named updates Amp exposes on the CLI:
    CLI amp plugins update <name>
    Or ask Amp: “Check if any of my imported plugins are out of date.”
  3. Review the proposed change. On hosted personal/workspace repositories, confirm commit/push when Amp asks.
  4. Reload the session: plugins: reload (Ctrl+O), then re-list. Walkthrough: reload and list.
  5. Smoke-test the plugin feature you care about before closing the thread.

Update vs reload vs re-add

  • Reload

    Same files, new session load. No upstream fetch. Use after local edits or a finished import.

  • Update / import refresh

    Pulls newer shared import content Amp manages via amp plugins update / import flows. Still reload afterward.

  • Re-run amp plugins add

    Useful for package ids and URL installs when update is not the documented path. Prefer the listing’s install block from the directory over inventing flags.

  • --auto-update

    Documented on some @amp/… packages (for example classic mode plugins Amp publishes). It keeps those packages current when Amp updates them; omit the flag to pin. It is not a global “update everything I ever installed” switch.

Failure branches

  • Update command errors or name unknown

    Wrong install channel — a bare file in .amp/plugins/ is not an import Amp can update for you. Replace the file manually or re-add from the listing, then reload.

  • Import conflict / dirty plugin repo

    Resolve the conflict in the personal or workspace plugin repository Amp cloned (amp plugins repositories / clone helpers). Do not force-push unless you own the repo and understand the impact on teammates.

  • Updated but behavior unchanged

    Forgot reload, or precedence still serves an older project copy. List sources, then follow not showing.

  • Expecting --auto-update on a random Git URL

    Only use --auto-update where Amp documents it for that package id. For community listings, re-run the published amp plugins add string when you intentionally want a newer fetch.

Success criteria

  • Upstream or import revision moved forward (or Amp reported already current).
  • amp plugins list still shows a healthy registration after reload.
  • The feature you updated still matches the author’s current docs.
