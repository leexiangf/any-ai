How to develop an Amp plugin

Minimal runnable skeleton, then the official Plugin API — not a mirrored long book.

Use this when you want to author a plugin, not just install one. Goal: a file Amp loads, a reload that picks it up, and a pointer to Amp’s API reference for everything beyond the skeleton. Concepts first? What is an Amp plugin.

Prerequisites amp --version

Amp CLI or app that can open a project; willingness to run third-party-shaped code on your machine (your own code counts). Amp also ships a built-in skill that can help write plugins — ask Amp if you prefer that path.

Shortest success path

  1. Skim the official Plugin API and Amp’s Plugins guide so you know tools vs commands vs events.
  2. Create a single-file plugin in the project load path:
    Path .amp/plugins/hello-amp.ts
  3. Use Amp’s documented entry shape (types from @ampcode/plugin):
    Minimal entry 
    import type { PluginAPI } from '@ampcode/plugin'

export default function (amp: PluginAPI) {
  amp.logger.log('hello-amp loaded')
}
  4. Reload and confirm: command palette Ctrl+O → plugins: reload, then
    Verifyamp plugins list
    Details: reload and list.
  5. Add one real capability next (a command or tool) using samples from the Plugin API docs — do not invent undocumented APIs here.

Single-file vs directory plugin

  • Single file

    A .ts or .js directly under a plugin location. Fastest local loop. Good for experiments and tiny tools.

  • Directory plugin

    Folder with index.ts (or index.js; Amp prefers index.ts if both exist) plus relative imports. Use this when you need helpers, prompts, or bundled skills.

  • Bundled skills

    Put a skill directory with SKILL.md under the plugin and call await amp.registerSkill({ path: 'skills/…' }). Amp does not auto-scan skills/. Full rules live in Amp’s Plugins doc — keep this page short.

After it loads locally

  1. Write a short README: what it does, install path, trust notes.
  2. Distribute the way Amp documents for your audience: project dir, Share URL into personal plugins, or amp plugins add for a fetchable single-file URL / package id.
  3. Optional: list on this community market via Submit so installers can copy a real command block.

Failure branches

  • File saved, list empty

    Wrong directory (not under .amp/plugins/ or another Amp load path), or forgot reload. Follow not showing.

  • Types / API mismatch

    Align with your Amp version and the current Plugin API. Prefer Amp’s kitchen-sink / examples over blog copies.

  • Skill folder present but unused

    Missing registerSkill call, or frontmatter name ≠ directory name. Fix registration; do not expect auto-discovery.

  • Trying to ship a novel mode without reading mode docs

    Custom agent modes are an advanced Plugin API surface. Start with a tool or command plugin; graduate to modes only with Amp’s current examples.

Success criteria

  • amp plugins list shows your plugin name/source after reload.
  • One registered tool or command behaves as you expect in a thread.
  • You know where to deepen: official Plugin API — not this market’s guide as the API source of truth.
