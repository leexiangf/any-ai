Amp plugin installed but not showing

Add looked fine — tools, modes, or Settings still look empty.

This guide is for the case where amp plugins add returned successfully (or you dropped files into a plugin directory), yet you cannot find the plugin’s tools, commands, or modes in the Amp UI you are using. If add itself errored, use amp plugins add failed first.

What people usually report amp plugins add … completed, but nothing new in the tool list plugin missing from Settings / mode picker / command palette

Also covers “it showed once, then vanished after a restart” and “lists in CLI but not in the editor-connected session.”

Shortest success path

  1. Ask the CLI what Amp actually loaded:
    CLIamp plugins list
    Note the plugin name, source, and whether events / tools / commands are registered.
  2. If the plugin is absent, re-run add with the listing’s exact string (example: @amp/oracle):
    Retry amp plugins add @amp/oracle
  3. If the plugin is present, reload without guessing: open the command palette with Ctrl+O and run plugins: reload (or plugins: list for an in-product view). See plugins: reload.
  4. Restart Amp if reload does not surface new tools, then re-check the same thread surface.
  5. Confirm you are looking in the right place: a tool plugin will not appear as a classic mode; a mode plugin will not invent a sidebar panel the author never registered.

Failure branches

  • Never registered (add silent / wrong scope)

    Machine-wide add and --target workspace write different locations. Project plugins live under .amp/plugins/; system plugins under ~/.config/amp/plugins/ (or %USERPROFILE%\.config\amp\plugins\ on Windows). Personal and workspace plugins come from Amp’s plugin repositories / Share import. Check the scope you intended, then amp plugins list again.

  • Loaded but not reloaded

    File drops and CLI adds often need an explicit plugins: reload or process restart before the current thread picks up new registrations. Reloading once is cheaper than reinstalling.

  • Wrong surface or wrong expectation

    Plugins register tools, commands, skills, or modes — not every UI chrome. Read the listing and author README for where the feature appears (mode picker vs tool search vs command palette). Searching the wrong surface looks identical to “not installed.”

  • Name collision / precedence

    Amp resolves same-named plugins in order: project → system → personal → workspace. A stub in .amp/plugins/ can hide a personal plugin you just imported. Temporarily move other copies aside, reload, and compare amp plugins list output.

  • Hosted repository limits (personal / workspace repos)

    Amp documents size and file-count limits for personal and workspace plugin repositories. A push can succeed while the oversized plugin is skipped at load time — it will not show in Settings or new threads. Trim runtime files or split the plugin, then reload. Project and system directories are not under those hosted limits.

Success criteria

  • amp plugins list shows the plugin with the expected source.
  • After plugins: reload, the tools / commands / modes named by the author are visible in the Amp surface you use.
  • A new thread (when required by the plugin) also sees the registration.
