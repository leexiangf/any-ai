amp plugins list

Shell command to inspect what Amp loaded — sources, tools, and which scope won.

Use this page when you need evidence that a plugin is registered, which directory or repo it came from, and whether another copy is winning on precedence. This is the inspect command. To refresh after an edit or install, use plugins: reload instead — do not paste the same walkthrough on both pages.

Command amp plugins list

In-product twin: command palette Ctrl+O → plugins: list. Prefer the shell form when you want a copyable audit trail.

Shortest success path

  1. Open a terminal where Amp’s CLI works:
    Checkamp --version
  2. List loaded plugins:
    CLIamp plugins list
  3. For each entry, note name, source path or repository, and registered tools / commands / events when Amp prints them.
  4. Compare against the listing you meant to install (example: @amp/finder). If the name is absent, go back to install or add failed.
  5. If the name is present but the UI is empty, leave this page and follow not showing (reload + surface).

How to read the output

Amp loads plugins from personal, workspace, project (.amp/plugins/), and system (~/.config/amp/plugins/ or Windows equivalent) locations. When two plugins share a name, precedence is project → system → personal → workspace. A “missing” personal plugin is often a same-named stub in the project directory winning the race.

Failure branches

  • amp: command not found

    PATH / install problem — fix guide. List cannot run until the CLI resolves.

  • Empty list after a successful-looking add

    Wrong scope (machine vs --target workspace), failed fetch that looked quiet, or you are in a different project directory than the one you installed into. Re-run add from amp plugins add, then list again from the same cwd you care about.

  • Listed, but wrong source path

    Precedence hid the copy you edited. Move or rename the winning stub, reload, then list again. Details on not showing.

  • Palette list and shell list disagree

    The shell reflects the CLI process environment; the palette reflects the Amp session you opened. Reload that session, or restart Amp, then compare both. See the combined walkthrough: reload and list.

Success criteria

  • amp plugins list runs without error.
  • The expected plugin name appears with a source you recognize.
  • You can decide the next step: install, reload, or stop chasing a missing UI entry.
