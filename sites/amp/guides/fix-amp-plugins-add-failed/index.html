amp plugins add failed

The Amp CLI ran, but install aborted before the plugin was registered.

Use this page when you can run amp, but amp plugins add exits with an error, hangs on fetch, or returns without listing the plugin afterward. If the shell says the command itself is missing, start with amp: command not found instead.

Typical messages amp plugins add … error: failed to fetch / 404 / not found permission denied · authentication required · private repository

Exact wording varies by Amp version. Treat any non-zero exit, or a success message that is not followed by the plugin in amp plugins list, as an add failure.

Shortest path that usually works

  1. Confirm the CLI is alive in a fresh terminal:
    Checkamp --version
  2. Open the install target in a browser. Prefer a listing from the Amp directory so you copy a known-good URL or package id — for example @amp/finder.
  3. Install with the documented CLI form:
    Machine-wide amp plugins add @amp/finder
    Or for the current project’s .amp/plugins/:
    Project amp plugins add @amp/finder --target workspace
  4. Verify registration:
    Verifyamp plugins list
  5. If the plugin lists but tools or modes stay empty, leave this page and follow installed but not showing (plugins: reload / surface checks).

Failure branches

  • URL or package id is wrong

    A GitHub tree page, README blob, or private gist often 404s for the CLI. Use the install string from the listing (package id like @amp/…, raw single-file URL, or Share URL Amp documents). Open it in a logged-out browser window before retrying.

  • Auth / private source

    Private repos need credentials the Amp CLI can use. Sign in to Amp first; do not paste a personal access token into a public thread. If the source must stay private, install via a Share URL into personal plugins, or copy a reviewed .ts / directory into ~/.config/amp/plugins/ or .amp/plugins/.

  • Wrong install surface

    amp plugins add without --target workspace installs for the machine (system/personal path Amp uses for URL adds). Project-only work should use --target workspace so files land under .amp/plugins/. Mixing those scopes looks like “add failed” when you check the other location.

  • Package is not a loadable plugin

    Amp expects a single-file .ts/.js or a directory with index.ts/index.js. A skill-only repo, empty tree, or oversized personal/workspace repository package can push successfully elsewhere and still never appear in Settings. Prefer a known listing, then re-check amp plugins list.

  • Network / proxy / TLS

    Corporate proxies and TLS inspection break fetches. Retry on a clean network, or clone the source locally and point Amp at a path Amp accepts for add / file drop. If amp --version works but every remote add fails, the problem is fetch, not the plugin id.

Success criteria

  • amp plugins add … exits without an error.
  • amp plugins list shows the plugin name and source.
  • After plugins: reload (command palette, Ctrl+O) or a restart, the tools / commands / modes the author documents are available in the Amp surface you use.
