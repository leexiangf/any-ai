amp: command not found

The shell cannot find the Amp CLI — fix install or PATH before any plugin command.

You searched this page because a terminal rejected amp plugins add, amp plugins list, or even amp --version. This is a host / PATH problem. It is not a bad plugin URL.

Copyable symptoms amp: command not found 'amp' is not recognized as an internal or external command amp: No such file or directory

IDE terminals, WSL, and PowerShell each keep their own PATH. A GUI Amp session can work while the shell you opened still cannot see amp.

Shortest success path

  1. Install or reinstall the Amp CLI from Amp’s current install instructions (install script, Homebrew tap, or Windows install script on ampcode.com). Prefer the documented installer over an outdated npm package name.
  2. Close the terminal completely, open a new one, then run:
    Checkamp --version
  3. If that prints a version, confirm plugin subcommands resolve:
    Checkamp plugins list
  4. Retry a known listing from this directory:
    Example amp plugins add @amp/finder
    Listing: @amp/finder.
  5. When amp runs but add errors, switch to amp plugins add failed.

Failure branches

  • CLI never installed (app-only or partial setup)

    Some editor integrations assume a shell binary that was never placed on PATH. Run the official Amp install for your OS, then verify with amp --version in the same kind of terminal you use for plugin commands (PowerShell vs cmd vs WSL vs macOS Terminal).

  • PATH not refreshed

    Installers append to user or system PATH, but an already-open terminal keeps the old environment. Quit the terminal app (not just the tab), reopen, and re-check. On Windows, sign out or reboot if a new user PATH still does not appear in IDE-embedded terminals.

  • Wrong environment (WSL vs Windows, nvm / asdf shims)

    Installing Amp on Windows does not put amp inside WSL, and vice versa. Version managers can shadow a global binary. Run where amp (Windows) or which amp / type -a amp (Unix) and confirm the path matches the install you just completed.

  • Stale package rename

    Older write-ups mention historic npm package names. Use Amp’s current install path from ampcode.com rather than inventing alternate global installs. After install, amp update (when available in your build) keeps the CLI current.

  • CI / headless shells without login PATH

    Non-interactive jobs often skip profile scripts that add Amp. Export the install directory explicitly in the job, or invoke the absolute path to the binary. For headless Amp usage, Amp documents access-token env vars separately from PATH.

Success criteria

  • amp --version prints a version string in the same shell you will use next.
  • amp plugins list runs (even if the list is empty).
  • amp plugins add … is reachable; further install errors belong on the add failed guide.
