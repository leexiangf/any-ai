How to install an Amp plugin

Three Amp-documented paths: CLI add, Share URL import, and plugin directories.

This is the install hub for Amp plugins on this market. Start here when you need a working install path, then jump to a command-word or fix page if something fails. Plugins run code in your environment — only install sources you trust.

Prerequisites amp --version # CLI available in your shell

Signed-in Amp for personal / workspace Share imports. A trusted URL, package id, Share link, or local .ts / plugin directory.

Path A — amp plugins add (CLI)

Best when a listing publishes a package id or single-file URL Amp’s CLI accepts. Details: amp plugins add.

  1. Pick a listing from Plugins and copy its CLI block. Example @amp/finder:
    CLI amp plugins add @amp/finder
  2. Optional: project-only install into .amp/plugins/:
    Project amp plugins add @amp/finder --target workspace
  3. Verify:
    Verifyamp plugins list

Path B — Share URL into personal plugins

Amp’s default path for shared plugins: paste the plugin’s Share URL into a thread and ask Amp to import it into your personal plugins (available everywhere you use Amp). Workspace admins can import into workspace plugins for everyone in the workspace.

  1. Open the listing and copy the Share / personal-import string when the author provides one.
  2. In Amp, paste a clear request, for example:
    Thread Import this shared plugin into my personal plugins: <share-url>
  3. Confirm Amp’s proposed repository change before push when prompted.
  4. Reload plugins in the current thread if Amp does not pick the import up automatically.

Path C — Drop files into a plugin directory

Amp loads project plugins from .amp/plugins/ at the repo root, and system plugins from ~/.config/amp/plugins/ (or %USERPROFILE%\.config\amp\plugins\ on Windows; honor XDG_CONFIG_HOME when set). Use a single .ts/.js file or a directory with index.ts/index.js.

  1. Review the plugin source before copying anything into those directories.
  2. Place the file or folder in the scope you want (project vs system).
  3. Run plugins: reload from the command palette (Ctrl+O), or restart Amp. Cross-check with reload and list.

Failure branches

  • amp: command not found

    Install or fix PATH — dedicated guide.

  • amp plugins add errors

    Bad URL, auth, or package — add failed.

  • Installed but invisible

    Scope, reload, precedence — not showing.

  • Wrong command for the artifact

    Some repos are skills or other Amp artifacts and use different install verbs on their listings. Always prefer the install block on the directory page over a generic amp plugins add guess.

Success criteria

  • amp plugins list shows the plugin, or Amp confirms a Share import.
  • After plugins: reload when needed, the feature appears in the surface the author documents (tools, commands, modes, or skills).
