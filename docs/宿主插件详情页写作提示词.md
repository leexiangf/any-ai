# 宿主插件详情页写作提示词

> 职责：为 **Any AI（aiaaii.com）某一宿主分店** 的**单个插件详情页**写/改厚正文——回答「是什么、解决什么、怎么装、怎么用、注意什么」。  
> 输出落点：`sites/{host}/items/{owner}/{slug}/index.html`（静态 HTML，不是独立 `articles/`）。  
> 借鉴来源：`docs/插件首篇介绍提示词.md`（DSH 首篇介绍）→ **裁剪后适配目录商场**；不搬独立文章层 / 强制 glossary / DSH 品牌句。  
> 与「宿主教程 guides」分离：生态级 How-to / 排错走 `sites/{host}/guides/`；本提示词只改**条目详情**。

项目：`d:\java_projects\mouse`（Any AI / AI-AAII 多宿主目录商场）

---

## 使用条件

仅在以下情况使用：

1. 新建某个插件详情页，或把现有薄页（仅 1 段 + install block）**加厚到可索引标准**。  
2. 用户指定宿主 + GitHub 仓（如 `kimi` + `obra/superpowers`），并要求按本规范重写。

日常只改分类索引 / sitemap / 商场 www：不要用本提示词。写跨宿主对比、报错长尾：走对应 guides 提示或直接改 guides 页。

## 输入（调用时填）

| 字段 | 示例 |
|---|---|
| 宿主 `host` | `amp` / `orca` / `droid` / `kimi` |
| 仓库 `owner/repo` | `obra/superpowers` |
| 详情路径 | `sites/kimi/items/obra/superpowers/index.html` |
| 分类 slug | `workflows`（须已存在或同步建分类页） |
| 一手源 | README · marketplace/plugin manifest · 官方 docs（有则 Source） |

**信息源优先级（高→低）：**

1. 仓库名 / 插件 id → Title、H1、正文插件名  
2. 仓库 description / 清单 description → 导语与「是什么」首句  
3. README / 官方安装文档 / 本站已有正确 install 块 → 安装与用法  
4. 禁止凭空功能、禁止编造命令或包名

## 分店命令词（写安装段时必须用真命令）

| host | 主安装命令（示意） | 店品牌 / 域 |
|---|---|---|
| `amp` | `amp plugins add <url>` | Amp Plugin Market · amp.aiaaii.com |
| `orca` | 产品内 Add marketplace source + Install；或文档化的 Git pin | Orca Plugin Market · orca.aiaaii.com |
| `droid` | `droid plugin marketplace add …` → `droid plugin install <plugin>@<mp> --scope user` | Droid Plugin Market · droid.aiaaii.com |
| `kimi` | `/plugins install https://github.com/<owner>/<repo>` → `/reload` | Kimi Plugin Market · kimi.aiaaii.com |

无真实安装/用法路径 → **不发布**或 noindex（继承轮子硬规则）。

## 允许 / 禁止修改

**允许：**

- 改写目标 `index.html` 的 `<title>` / `meta description` / `page-hero` 导语 / `main.prose` 正文  
- 保留并校正 `install-block`、`meta-table`、`source-line`  
- 增补 FAQ（`<div class="faq">`）、兼容说明、编号步骤  
- 必要时同步 `items/index.html`、分类页卡片 one-liner（一句事实，勿扩写成长文）

**禁止：**

- 镜像粘贴上游 README 大段原文  
- 冒充官方 / 使用保留厂商身份  
- 编造 star、版本、未文档化的 CLI  
- 外链非一手源（默认只链 `https://github.com/...` 与本站内链；官方 docs 仅作 Source 行）  
- 改 `styles.css` / `theme.js` / 全局页眉页脚结构（除非修坏链）  
- 把详情页写成独立「首篇介绍文章站」；**不要**新建 `articles/` 目录（除非用户另立资讯站立项）

## SEO 字段

### Title

```text
{插件名} - {一句话角色} | {店品牌}
```

- 含插件名；角色来自真实能力，≤ 一短句  
- 总长建议 ≤ 60–70 字符（英文）  
- 禁止具体 star / 版本号  

### meta description

- ≤ 160 字符；**首句给答案**（是什么 + 对谁有用）  
- 自然带插件名 + 宿主主词（如 `Kimi plugin` / `Amp plugin`）  
- 可点到「community listing / install」；勿堆砌无关词  

### H1 / 导语

- H1 = 插件名（或清单显示名）  
- 导语 1 句 = description 的口语版（80–160 字量级），放在 `page-hero`  

### 品牌命中（轻量）

全文至少 1 处自然出现店品牌或商场品牌之一即可，例如：`Kimi Plugin Market` / `Any AI`。  
**不要**每个 H2 硬塞品牌；**不要**照搬 DSH 的强制「DSH Plugin」句式。

---

## 正文结构（固定骨架）

页面 chrome（header / footer / theme）保持与同店其他详情页一致。  
`main .prose` 内按下列顺序输出（H2 主题固定，措辞可问句化并带插件名）：

```html
<!-- 1. 导语段可与 hero 分工：hero 一句，此处展开 2–4 句 -->
<p><strong>{插件名}</strong> …（首次出现可链本页或不链；勿重复堆链）</p>

<!-- 安装块：主通道 + 必要时备通道；label 说明用途 -->
<div class="install-block"><span class="label">…</span><code>…真实命令…</code></div>

<!-- meta-table：Author / Category / Status / Source -->
<dl class="meta-table">…</dl>

<h2>{插件名} 是什么？</h2>
<!-- 段首加粗结论：「{插件名} 解决 …」；再展开；关键事实可 (Source) -->

<h2>{插件名} 的核心功能</h2>
<!-- ul：3–6 条真实能力；每条独立成句，可被引用；来自 README -->

<h2>怎么安装与启用 {插件名}</h2>
<!-- ol：编号步骤 = 动作 + 预期结果；命令完整可复制 -->

<h2>{插件名} 典型用法</h2>
<!-- ol：1–3 个真实用法；无文档则写「见仓库 README 示例」+ 链 GitHub，勿编造 -->

<h2>适用场景与注意</h2>
<!-- 适用谁 / 限制 / 兼容 / 信任提示（第三方代码） -->

<div class="faq">
  <!-- 4–6 条；见下 -->
</div>

<p class="source-line">Independent rewrite · Updated YYYY-MM-DD · Not affiliated with {VENDOR}</p>
<p><a href="/items/">← All plugins</a> · <a href="/categories/{slug}/">Category</a></p>
```

### Answer-First

每个 `h2` 后**第一句**必须是脱离标题也成立的结论（「X 是 Y」或「要做 Z 就执行 W」），建议 `<strong>…</strong>`。禁止设问铺垫开头。

### 安装与用法

- 必须用该宿主**真实**命令；多步用 `<ol>`  
- 每步写清预期（例如「Installed 列表出现 id」「需 `/reload`」）  
- Orca / 纯 UI 安装：用编号描述产品内路径，仍算「真实用法」  

### 外链与内链

| 类型 | 规则 |
|---|---|
| 外链 | 默认仅 `https://github.com/{owner}/{repo}`（及官方 docs URL 作 Source） |
| 内链 | 分类 `/categories/{slug}/` · 目录 `/items/` · 相关 guide（若有）· 商场 `https://aiaaii.com/`（页脚已有则正文可不重复） |
| FAQ 内 | **禁止超链接**（与 DSH 首篇一致，便于摘要干净引用） |

## FAQ 规则（4–6 条）

```html
<details>
  <summary>{完整问句，具体到本插件}</summary>
  <p>{首句独立结论。再 1–2 句补命令或边界。}</p>
</details>
```

- **禁止**套用「这是什么插件 / 怎么安装 / 怎么重启」万能三件套（安装细节已在正文时，FAQ 挖配置坑、范围、依赖、报错）  
- q 换成别的插件名就说不通  
- a 可含命令，**严禁编造**；不写 star / 日期 / 版本号（版本以 Source 为准）  
- 至少 1 条自然带宿主主词（如 “Kimi plugin” / “Droid marketplace”）即可，勿堆品牌  

条数：默认 **4**；信息充足可到 **6**；宁缺毋滥。

---

## 可选：相关术语（glossary）

仅当 README 有**专有名词 / 易搜别名**时，在 FAQ 前或后加一小块：

```html
<h2>相关术语</h2>
<dl class="meta-table">
  <dt>{Term}</dt>
  <dd><strong>{Term} 是 …</strong> …（来源：README）</dd>
</dl>
```

- 2–3 条即可；definition 首句「X 是 Y」  
- 无专词则**整节省略**（不要为凑结构编术语）

## 语言

| 店 | 默认 |
|---|---|
| amp / orca / droid | 英文页（与现网一致） |
| kimi | 英文可先上；若用户要求中文，可另做中文导语+FAQ，或后续双语立项 |

中英若成对：事实必须一致，不要求逐字翻译。

## 与 DSH「首篇介绍」的差异（避免误用）

| DSH 首篇 | 本站详情页 |
|---|---|
| `articles/introduction.*.md` | `sites/{host}/items/.../index.html` |
| 强制 6 FAQ + glossary + 中英成对 | FAQ 4–6；glossary 可选；语言按店 |
| 品牌强制 `DSH Plugin` | 轻量命中店品牌 / Any AI |
| 独立文章 URL | 详情即长尾页；教程另走 guides |
| frontmatter / JSON-LD 术语集 | 先把可见 HTML 写厚；Schema 另议 |

## 验收清单

- [ ] 只改约定文件；未镜像 README  
- [ ] Title / description / H1 导语 / 正文核心三者同一主题  
- [ ] description ≤160 且首句给答案  
- [ ] H2 六段主题齐全（是什么 / 功能 / 安装 / 用法 / 注意 + FAQ 区）；Answer-First  
- [ ] 安装命令真实可执行；步骤编号  
- [ ] meta-table Source 指向一手仓；source-line 含 Independent rewrite + 日期 + Not affiliated  
- [ ] FAQ 4–6，问句具体，答案无外链、无编造  
- [ ] 同店 `items/` 与分类卡片 one-liner 未与正文事实矛盾  
- [ ] 本地打开或部署后安装块可复制、内链有效
